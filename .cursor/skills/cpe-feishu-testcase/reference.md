# 飞书用例字段参考

本文档**仅界定**飞书项目 8 个用例字段的含义、格式与填写要求。  
判级与模块矩阵见 [test-strategy.md](test-strategy.md)；场景示例见 [examples.md](examples.md)。

---

## 字段总览

| # | 飞书字段名 | 必填 | 说明 |
|---|------------|------|------|
| 1 | 关联项目 | 是 | 飞书空间中的**项目名称** |
| 2 | 用例名称/标题 | 是 | 团队标题格式，见 §2 |
| 3 | 用例类型 | 是 | 枚举见 §3 |
| 4 | 用例分级 | 是 | P0 / P1 / P2 / P3，见 §4 |
| 5 | 标签 | 是 | 项目/模块标签，见 §5 |
| 6 | 前置条件 | 是 | 环境、版本、拓扑、初始状态 |
| 7 | 测试步骤 | 是 | 编号、可执行、一步一操作 |
| 8 | 预期结果 | 是 | 可判定，与步骤对应 |

---

## 1. 关联项目

**含义**：用例归属的飞书项目（空间内项目全名）。

**不是**：

- 产品型号（写在标题 `【型号】` 与前置条件）
- 项目标签缩写（写在标题 `【LLA】` 与字段 5）

| 概念 | 填写位置 | 示例 |
|------|----------|------|
| 飞书关联项目 | **字段 1** | `xxx研发项目`（团队维护正式名） |
| 项目标签 | 标题、`字段 5` | `LLA` |
| 产品型号 | 标题 `【型号】`、前置 | `EVO6022GP3`、`SR7D4VA` |

未确定时填 `TBD_FEISHU_PROJECT`，生成后由人工替换。

---

## 2. 用例名称/标题

**含义**：飞书中的用例标题，须可独立表达测什么。

**格式**（团队统一）：

```text
【<产品型号>】【<项目标签>】【<模块>】<功能描述>；
```

| 段 | 要求 |
|----|------|
| 产品型号 | 全大写，与 DUT 一致 |
| 项目标签 | 飞书项目缩写，如 `LLA` |
| 模块 | 功能域：`WAN`、`LAN`、`WIFI`、`ACS`、`TR069`、`OLT`、`UPG`、`SYS` 等 |
| 功能描述 | 完整中文句：默认态、操作、结果或边界；句末可用 `；` |

**要求**：

- 一条用例一个核心测试点；双向场景可写「也支持改回…」或拆两条（见 [examples.md](examples.md)）。
- 禁止空洞标题（如「测 WiFi」「ACS 测试」）。

**示例**：

```text
【EVO6022GP3】【LLA】【WIFI】2.4G 频段默认加密与关联成功；
```

---

## 3. 用例类型

**含义**：用例分类，与飞书项目配置保持一致。

| 推荐值 | 适用 |
|--------|------|
| 功能测试 | 业务功能、配置、协议、页面/CLI |
| 性能测试 | 吞吐、时延、峰值（非功能门禁时常与分级 P1/P2 配合） |
| 兼容性测试 | OLT/终端/浏览器/光模块等 |
| 安全测试 | 过滤、权限、远程管理安全 |
| 可靠性测试 | 拷机、开关机循环、长稳 |
| 回归测试 | 缺陷或版本修复验证 |
| 冒烟测试 | 发版最小路径 |

用户或飞书已配置其它枚举值时，**以项目配置为准**。  
未说明时默认 **功能测试**。

---

## 4. 用例分级

**含义**：用例执行优先级 **P0 / P1 / P2 / P3**（四选一）。

| 级别 | 字段 4 填写 |
|------|-------------|
| P0 | `P0` |
| P1 | `P1` |
| P2 | `P2` |
| P3 | `P3` |

**如何取值**：由 [test-strategy.md](test-strategy.md) 自动判定。  
批量输出时可在矩阵增加 **分级依据** 列（非飞书必填，便于评审）。

可选：在字段 4 下增加引用块说明依据，例如：

```markdown
### 4. 用例分级
P1

> 分级依据：P1 | 策略:WEB-WIFI-扩展 | 访客 WiFi
```

---

## 5. 标签

**含义**：飞书用例标签，用于筛选与统计。

**规则**：

- **至少包含**项目缩写（如 `LLA`）。
- 可与标题中【模块】一致地增加模块标签（如 `WIFI`、`ACS`）。
- 多标签使用英文逗号，无空格：`LLA,WIFI`。

| 标签示例 | 说明 |
|----------|------|
| `LLA` | 项目缩写（常见必填） |
| `LLA,ACS` | 项目 + ACS/TR069 类 |
| `LLA,WIFI` | 项目 + 无线类 |

标题 `【ACS】` 与字段 5 是否重复由团队习惯决定；**默认**模块相关用例写 `LLA,<模块>`。

---

## 6. 前置条件

**含义**：执行步骤前必须满足的环境与状态。

**建议结构**（bullet 列表，无则写 N/A）：

| 项 | 说明 |
|----|------|
| DUT | 型号、硬件版本、**软件版本** |
| 初始状态 | 出厂默认 / 恢复出厂 / 已导入模板；写明关键默认（如默认 WAN 方式） |
| 拓扑 | 上联、LAN/Wi‑Fi 下挂（IP/账号用占位符） |
| 依赖 | 如需先上网、先上线网管等，一句话说明 |
| 工具/账号 | 测试环境专用占位，**禁止真实密码** |

---

## 7. 测试步骤

**含义**：可重复执行的操作序列。

**格式**：

- 使用阿拉伯数字编号：`1.` `2.` `3.`
- **一步一操作**；含必要数据、界面路径或操作对象（未知用 `TBD`）
- 需要分阶段时在步骤内用 **阶段一 / 阶段二** 小标题

**禁止**：一步内堆砌多个无关操作；只有结论没有操作。

---

## 8. 预期结果

**含义**：各步骤的通过判定标准。

**格式**：

- 与步骤 **编号一一对应**（推荐 `1.` 对 `1.`）
- 结果须 **可观测、可判定**（页面状态、指示灯、获 IP、ping、日志关键字等）
- 失败时需采集的信息可写在对应预期末条或前置中（占位符，不写真实路径/密码）

**禁止**：仅写「正常」「成功」而无判定条件。

---

## 字段与输出模板对照

生成用例时 8 个字段名**不得修改**：

```markdown
### 1. 关联项目
### 2. 用例名称/标题
### 3. 用例类型
### 4. 用例分级
### 5. 标签
### 6. 前置条件
### 7. 测试步骤
### 8. 预期结果
```

完整示例见 [examples.md](examples.md)。
